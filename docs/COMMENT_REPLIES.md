# 评论与回复

文章讨论以主评论为单位展开。回复主评论或其中某个人，均放在同一层回复列表，不继续增加缩进；回复显示实际回应的对象。主评论和回复各自按时间顺序、独立游标连续加载。未展开时不请求回复。

## 读者操作

- 登录后点击「回复」，在对应评论下输入。切换回复对象、取消后重新打开会保留本页草稿；主动退出或切换账号会清理草稿。
- 每条回复最多 5000 个 Unicode 码点。失败保留输入，同一内容重试沿用幂等键，避免请求已完成但响应丢失时重复发表。
- 写入成功后清理对应输入并显示统一 toast。若后续列表读取失败，提示回复已发表并提供读取重试，不重新发表。
- 游客可以阅读和展开讨论，不显示点赞、回复、删除或输入框。关闭评论开关后保留历史讨论，停止新评论与回复。
- 手机只保留一层讨论关系与至少 44px 操作高度；回复作者有文章作者标记。评论正文按纯文字转义展示。

草稿仅在当前页面内存中保留，不属于编辑器 IndexedDB 恢复点。页面关闭或刷新后需要重新输入。

## 接口

| 方法 | 路径（省略 `/api/v1`） | 行为 |
| --- | --- | --- |
| GET | `/posts/{postID}/comments` | 仅返回当前公开主评论，含 `reply_count` |
| GET | `/comments/{rootID}/replies` | 返回该主评论下公开回复；支持 `cursor`、`limit` |
| POST | `/posts/{postID}/comments` | `{ "body": "正文", "reply_to_id": "目标评论ID" }`；不传目标则为主评论 |
| DELETE | `/comments/{id}` | 本人或站长软删除，沿用原有权限 |
| PUT / DELETE | `/comments/{id}/like` | 沿用原有点赞接口 |
| PUT | `/admin/comments/{id}/visibility` | 站长隐藏／恢复，保留审计原因 |

写入沿用会话、访问策略、CSRF、限流和 `Idempotency-Key`。目标必须是同一篇当前公开文章中的可见评论；服务器推导主评论 ID，客户端不能自行指定树结构。主评论和回复的签名游标互不通用，也不能跨文章、跨讨论串使用。个性化评论结果使用 `private, no-store`。

评论投影增加 `parent_id`、`reply_to`、`reply_to_deleted`、`is_author`、`reply_count` 与 `thread_reply_count`。后者是当前可见讨论串的回复总数，幂等重试也重新读取当前投影。后台额外返回 `reply_to_id`、`is_reply`，以便辨认操作范围。ID 始终是字符串。

## 数据与并发

迁移 `0026_comment_replies.sql` 在 `comments` 中加入可空的 `parent_id`、`reply_to_id`，已有评论继续作为主评论。复合同文外键、形状检查和触发器保证：主评论无父节点；回复父节点必须是主评论；实际目标属于同一讨论串；身份、文章与回复关系创建后不可改写。读取索引分别覆盖公开主评论、公开回复和被回复对象。

创建、删除、隐藏和点赞沿用文章行锁序列化，写入评论与 outbox 事件在同一事务提交。幂等重试不会重复生成评论或事件；返回响应前再次读取当前可见投影，避免重放已经不可见的正文或目标身份。

新评论及回复还会在同一事务生成[站内通知](NOTIFICATIONS.md)。通知链接可以有界读取首屏之外的目标讨论；普通评论列表、回复对象与写入协议沿用原规则。

隐藏或删除主评论后，整段讨论不再公开读取、回复或点赞，公开评论数排除其中回复；回复记录及各自状态保留。恢复主评论只恢复原本可见的回复，不恢复被单独隐藏或删除的内容。隐藏或删除某条回复不影响其余回复；原先回复该对象的条目只显示「原评论已不可用」，不继续显示其身份。软删除不能通过恢复可见接口撤销。

部署前备份并完成隔离恢复验证，再执行增量迁移、切换二进制并验证内网与外网。配置、域名、Tunnel 和现有业务数据保持原值。不执行破坏性的降级迁移。

## 验证范围

PostgreSQL 18 集成测试覆盖：旧主评论兼容、回复对象、幂等与事件唯一性、跨文章拒绝、认证和 CSRF、开关、Unicode 长度、独立分页、撤回、隐藏／删除、身份隐藏和数据库树约束。浏览器回归使用真实 Vue 组件与隔离 API fixture；运行中版本另在独立数据库中验证真实读写。浏览器手机视口验证不等同于真机验证。
