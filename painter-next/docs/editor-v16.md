# V16：同一篇文章，一个编辑页面

本次保留 Painter 的纸墨蓝与现有编辑/保存链路，收拢两种正文表示带来的布局分叉。作者进入页面即可编辑文档；Markdown 源码是顶部“更多”中的次要操作。

## 页面规则

- 标题、文档格式工具和正文使用同一阅读宽度与文字起点。长标题使用自动高度文本框，随内容、字体和窗口宽度增长或收缩，不再横向隐藏开头或结尾。移除文档/源码大标签行，给正文留出连续空间。
- 摘要、标签、封面和时间设置始终只有一份 DOM。宽屏保持同一个 280px 右侧信息栏；窄屏保持标题后的同一个折叠区。切换正文表示不改变其位置、宽度或展开选择。
- 源码只替换正文区域，初始使用单栏编辑。原有编辑/预览/分屏仍可使用；返回文档保留文章信息。
- “更多”提供源码入口与 Markdown 导出，支持 Escape、外部点击和键盘离开关闭。窄屏菜单相对于整个命令区定位，避免换行后出界。
- 手机的文档格式工具保持单行，可水平滚动；44px 操作目标与键盘访问保留。选择器仍使用 Painter 自己的控件。

## 真实参考与取舍

[WordPress 官方编辑器说明](https://wordpress.org/documentation/article/wordpress-block-editor/)把默认视觉编辑、内容工作区、文章设置与更多操作分开，源码访问位于更多选项。这里采用这一操作层级，不引入 HTML 代码编辑器或 WordPress 的区块体系。

[WordPress 官方文章设置侧栏](https://wordpress.org/documentation/article/page-post-settings-sidebar/)把摘要、封面和标签归在文章层级设置中。这里保留 Painter 现有字段与单一信息栏，不因正文表示变化重新排列这些设置。[Ghost 官方编辑器说明](https://ghost.org/help/using-the-editor/)也作为写作工具与发布设置分离的参考。

这些参考只影响页面组织，不新增托管编辑器、协作服务或额外技术栈。

## 数据与安全边界

正文仍通过原有 Tiptap 与 CodeMirror 双向绑定到同一 draft。没有改后端、接口或数据库。初始化锁定、自动保存、明确检查点、版本冲突/手动合并、本地恢复、修订恢复确认、媒体引用及发布快照继续使用原有代码。

不能安全表达的 Markdown 仍完整进入源码，并显示保存原文的说明；返回文档操作在这种状态下不可用。源码和导出都不擅自转换原文。中文输入法组合期间阻止切换，完成输入后可继续。

## 验证方式

`tests/browser/v16-editor.cjs` 对 1920、1440、900、390、320 宽度与深浅主题检查 DOM、边界和操作。源码不仅检查行容器位置，还逐字测量前两非空行的前八个非空白字符，用 Range 与实际命中结果确认 Markdown 前缀和正文首字没有被 sticky 行号栏遮挡；长标题检查完整内容可见以及窄化后增长、放宽后收缩。文章内容为明确的隔离夹具，拦截业务写入，不修改正式数据，不生成截图。

同一入口默认继续运行 V11 的初始化、冲突、恢复与修订锁定工作负载，只在内存中把旧模式标签定位适配成新的更多入口；不重写旧测试记录。`RUN_SAFETY=0` 只在单独检查布局时跳过该部分。最终截图、视觉复核与检测由 V16 的统一验收批次提供。

初轮候选服务的 153 项布局交互检查与 43 项原安全检查通过，但统一截图复核发现行号栏遮挡首字，暴露了只测行容器边界的不足。已移除行号栏的负外边距，改为正常占据左侧留白，并补充上述逐字可见性断言。修复后的最终候选服务退出码为 0：177 项布局与交互检查、43 项原安全检查全部通过；浏览器错误、意外业务请求、实际业务写入和本测试生成的截图均为 0。结果记录在 `tests/artifacts/v16/editor/report.json` 和 `tests/artifacts/v16/editor/safety/report.json`；视觉效果仍以统一截图复核为准。
