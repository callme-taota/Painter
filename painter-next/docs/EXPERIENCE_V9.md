# V9：工作台导航层级

原侧栏把内容、运营、站点配置、个人账户和“写新文章”动作并列，页面越多越难判断归属。V9改为职责分区与页面入口两层，保留现有URL、业务接口、权限和存储结构。

| 一级分区 | 二级入口（站长视角） | 归属原则 |
| --- | --- | --- |
| 内容管理 | 文章管理、片语、标签管理、评论治理 | 创作、组织和治理内容 |
| 数据与运维 | 站点访问分析、存储与任务 | 观察运行情况和处理后台任务 |
| 站点管理 | 网站信息、功能与通知、登录安全、成员权限 | 全站配置与访问治理 |
| 个人空间 | 个人资料、收藏文章、关注与粉丝、阅读足迹、我的媒体、登录会话 | 当前账号自己的资料、关系和资源 |

“写新文章”是文章页的主操作，不占侧栏栏目。个人媒体继续归个人空间，不能因站长角色而误称全站媒体库。作者的入口称“我的文章”“我的文章分析”，统计仍只请求自己的文章范围。读者只显示个人空间；过滤不可用叶子后移除空组。隐藏菜单不代替服务端鉴权。

## 交互与位置合同

一级按钮支持鼠标、Enter、Space展开/收起，使用aria-expanded和aria-controls；二级为真实链接，唯一当前项设置aria-current。到达页面时默认展开当前分区，其他分区按账号记住本标签页的展开偏好；sessionStorage不可用时退回默认状态。不会把该偏好写入数据库或跨设备同步。

当前项在独立侧栏滚动区内自动定位；只调整该滚动区，不移动任务画布。用户手动展开其他组时不会抢走滚动位置。手机打开抽屉后再定位当前项，Escape关闭并恢复菜单按钮焦点。

页面上方用“分区 / 页面”位置提示连接侧栏与内容。新建、编辑文章均选中文章父入口，并补充第三段位置；关注与粉丝共用一个入口。设置页以#site/#features/#security分别深链接，未知hash回到网站信息；侧栏、内容面板与浏览器前后退同步。桌面不再重复展示设置页tabs，手机保留便于操作的页内tabs，共用同一位置状态。切换同页hash不会重载并抹掉未保存的本地表单。

## 实现与扩展

`web/frontend/src/navigation.ts`集中声明NavigationGroup/NavigationItem及角色、别名、文章父项和设置section匹配；StudioSidebar负责展开/定位与渲染，App负责页面位置、设置hash及抽屉打开。面包屑和侧栏使用同一匹配结果，避免两份路由判断随新增页面漂移。

新增页面先明确资源属于全站还是个人，再加入对应children，声明role和必要的别名；相同职责优先复用现有分区。URL及后端鉴权应先成立，再开放导航。当前只有两层，没有增加三级树、动态导航数据库或新的前端路由框架。

本轮没有迁移、业务写入协议或运行依赖变化，schema保持12，仍为嵌入前端的Go单体与PostgreSQL18。封面、编辑器、搜索、安装、GitHub与鉴权合同沿用既有实现；MFA仍是V7规划。
