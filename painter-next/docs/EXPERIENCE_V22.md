# V22：首页内容与游戏、唱片、照片墙

本轮让首页内容可由站长编排，并增加 Steam 游戏墙、Apple Music 唱片墙和自己的照片墙。沿用现有 Painter 标识、中性浅深色、DOM 层叠纸页和暖色滚动背景，不替换既有视觉方向。

## 默认状态与首页编排

站点管理 → 首页内容（`/studio/home`）仅对 owner 开放，分为「页面内容 / 展示墙 / Steam 设置」。默认保留现有介绍、最近6篇公开文章与结尾；三个新墙关闭且没有预置条目。没有默认账号连接、伪造的游玩记录、专辑收藏或个人照片。

六个区块始终保留在配置中，可分别启停、用上移 / 下移调整顺序、修改标题、说明和可选链接：

| 区块 | 内容 | 数量规则 |
| --- | --- | --- |
| `intro` | 问候、姓名、简介、身份与兴趣、写作场景文案 | 不使用数量字段 |
| `articles` | 真实公开文章 | 0–12，默认6；0隐藏 |
| `steam` | 保存的 Steam 游戏条目 | 0–24；0或没有可见条目时隐藏 |
| `music` | 保存的 Apple Music 专辑条目 | 0–24；0或没有可见条目时隐藏 |
| `photos` | 自己上传的照片条目 | 0–24；0或没有可见条目时隐藏 |
| `closing` | 结尾文案与链接 | 不使用数量字段 |

数量限制是首页显示上限，不是内容库容量；条目库独立分页管理。区块标题 / 写作标题最多80个 Unicode code points，说明 / 写作说明最多600，链接文字与滚动提示最多60。姓名最多80，身份与兴趣最多12项、每项60。标题和说明支持换行。

介绍默认沿用「网站信息」中的姓名、简介和身份；也可关闭继承，单独设置首页介绍。写作标题、写作介绍、向下探索提示均可修改。结尾说明留空且继承网站介绍时使用介绍姓名回退。滚动视差与背景渐变各有开关，同时尊重系统减少动态效果偏好。无 JavaScript 时仍按文档流阅读；所有区块关闭时保留导航、页脚和可访问的页面标题。

## 展示墙与条目管理

展示墙使用紧凑的分页表格，显示图片、标题、可见性、排序和编辑 / 删除操作。编辑器一次处理一个条目；列表计数明确为「第N页 · 本页N项」，不冒充全库总数。排序按 `(position,id)` 稳定排列，`position` 范围0–1000000。

手动新条目默认隐藏。要公开，需同时满足：**条目显示已保存、对应区块已开启、首页显示数量大于0**。隐藏的条目和上传队列不进入公开首页。标题最多80字符，单行副标题最多600，图片说明最多200，均按 Unicode code points 计数。

游戏用实际封面组成展架，唱片使用方形封面及官方 Apple Music 入口标识，照片使用带说明的响应式画廊。照片的原图链接无 JavaScript 可用；增强后复用键盘图片查看器，支持上一张 / 下一张、Escape 和关闭后的焦点返回。不会用虚构封面替代尚未提供的内容。

### Steam

可以输入 Steam App ID 或商店链接读取公开信息。结果只是预览，点击「用于新条目」填入编辑器后，仍须核对并保存；读取失败可手动填写标题、目标链接并上传自己的封面。

可选的账号同步需要先保存17位 Steam ID64 和 Web API Key，再选择已拥有游戏或最近游玩。密钥加密保存在服务器，只显示「已配置」，不回显；留空保留原密钥，明确勾选才移除。修改未保存时不能开始同步。

「立即同步」显式刷新本地快照；自动同步为可选的每6小时尝试，失败有退避。可见结果取决于 Steam 的资料 / 游戏隐私。请求失败、空返回或隐私限制不会用空集合覆盖上次成功数据。页面显示真实上次同步时间和脱敏错误，不宣称当前已连通任何实际账号。

同一同步游戏被人工编辑后标记 `local_override`，后续同步更新该游戏时保留人工标题、副标题、链接和封面；显示、顺序、自选媒体和图片说明也保留。成功切换快照会移除本次集合之外的旧同步游戏，手动条目不受影响。删除同步条目不是永久屏蔽，下次同步可能再次导入；希望持续不展示时应设为隐藏。

### Apple Music

导入对象为 **Apple Music 专辑链接**，服务器通过公开 iTunes 目录读取标题、艺人、封面和链接，再交给站长核对保存。不是私人播放历史、歌单同步、MusicKit 授权或付费音乐播放服务。页面链接到实际专辑，官方标识只是入口标识，不表示账号已经连接。

公共目录返回的封面可能是小图。需要更清晰的封面时，可上传自选高清图片覆盖平台封面；不会承诺把目录小图自动处理成高清图。

### 自己的照片与封面上传

照片必须引用本人可用的已上传媒体；游戏 / 唱片可使用平台封面，也可上传自选封面覆盖。支持 JPEG、PNG、WebP、GIF；单图上限读取私有首页响应的 `max_image_bytes`，缺省回退10 MiB，不在前端固定假定所有部署都是10 MiB。

多张照片依次上传到私有待核对队列，每张显示真实等待 / 上传 / 成功 / 失败状态。失败可使用原始文件和原幂等键重试，排队或失败项可取消，其它成功项保留。每张照片须点击「编辑并保存」，核对标题、图片说明、排序和显示开关后保存为条目，不会因选择文件而自动公开。

照片可填写目标链接，保存后说明区提供可点击的跳转入口；照片本身仍用于原图预览。

移除或删除条目不直接删除物理图片。所有首页条目引用（包括隐藏条目）均保护媒体删除与 GC；只有引用移除后，媒体才重新按既有清理规则处理。上传队列和未保存表单不是持久离线恢复；切换或离开时会提示未保存内容。

## 数据、接口与上游边界

schema17 为追加迁移，新增 `homepage_settings`、`homepage_items`、`homepage_import_cache` 和 `homepage_provider_rates`。配置和条目各有版本，写入沿用 owner 权限、CSRF、CAS、幂等和审计；上传继续使用现有 `/api/v1/media`。初始读取失败不允许把空表单保存为配置；冲突保留输入，确认后才能用精确 GET 载入服务器最新内容。

| 动作 | 接口（`/api/v1` 前缀） |
| --- | --- |
| 读取 / 保存首页配置 | `GET /admin/home`、`PUT /admin/home` |
| 条目分页 | `GET /admin/home/items?kind=steam\|music\|photos&limit=20&cursor=…` |
| 精确读取条目 | `GET /admin/home/items/{id}` |
| 创建 / 修改 / 删除条目 | `POST /admin/home/items`、`PUT /admin/home/items/{id}`、`DELETE /admin/home/items/{id}` |
| 读取导入预览，不创建条目 | `POST /admin/home/import`，`{kind,input}` |
| 立即同步 | `POST /admin/home/steam-sync`，使用已保存配置版本 |

配置主体为 `{config,steam}`；`config` 保存六区块的顺序、开关和文案，`steam` 保存 ID、模式及自动同步选择，`api_key` 可选写入，`clear_api_key` 明确清除。条目主体为 `{kind,title,subtitle,alt,url,image_url,media_id,provider_id,position,visible}`，`source` 和 `local_override` 由服务器维护。首页内容库合计最多5000项，分页上限50，首页显示数量不改变库上限。

访客的服务器渲染只读取本地配置、已保存的平台元数据 / 图片引用和公开文章，不临时调用 Steam 或 iTunes 接口。导入与同步只在独立管理操作 / 后台任务中请求受限的平台地址，并使用缓存与请求边界。浏览器仍会按保存的官方 CDN 地址加载平台封面；上传照片使用站内媒体，不把「SSR不请求平台接口」误说成所有图片都已下载到本站。密钥及私有同步配置不进入公开 DTO 或 HTML。

## 验证与发布状态

收尾评审发现后台文本域的通用背景 / 边框规则覆盖了复选框勾选态。共用 studio 样式现排除 checkbox / radio，恢复共享选中底色及标记，并补齐半选横线；禁用透明度、键盘焦点和强制颜色模式继续沿用共享规则。这项修正覆盖所有后台选择控件，不依赖首页局部样式。唯一 P2 视觉问题已通过重建后的定点复验关闭。

候选内容和上游响应 fixture 仅用于隔离测试环境，不是站长真实游戏库、唱片收藏或照片，也不应随程序升级带入正式数据。现有文章、动态及其发布链路不在本轮重写范围。
