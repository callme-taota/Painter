# Painter 全端体验与交互规范

版本：V44 · 2026-11-13

适用范围：桌面 Web、平板 Web、手机 Web，以及未来原生客户端的共享契约。当前项目是 Go SSR + Vue 交互增强的 Web 产品；本文不会把手机网页、浏览器模拟视口或可安装图标称作原生 App。本文规定交互目标，实际完成与测试证据须在对应发布记录中逐项注明。

## 1. 体验目标与执行级别

手机以单手浏览、短时阅读、随手记录和专注处理一个任务为主；桌面以连续阅读、内容管理和长文创作为主。两端共享内容、身份、权限与设计原则，但不要求相同位置、信息密度和操作路径。

- **MUST**：新增或修改相关界面时必须满足。未满足的条目须标明范围与原因，不能据此文档宣称全站已经合规
- **SHOULD**：默认采用；确有内容、平台或性能原因时可调整，并在实现说明中记录
- **后续能力**：只规定未来接入边界，不代表当前实现已实现

**MUST** 保持：原 Painter logo、黑白灰主界面、实色工作区、用于正文链接及明确阅读动作的苹果蓝、公共导航与搜索的指定 Liquid Glass 材质。站点标题和界面标签不添加装饰性句号；不改写作者正文、引用与真实项目名称中的标点。

**MUST** 优先采用当前源码和用户确认的视觉约束。旧版 `PRODUCT.md` / `DESIGN.md` 中诸如所有导航实色、所有手机沿用右侧 Dock、滚动统一暖色等历史描述，不得覆盖当前实现与本规范；历史记录不作为重新引入旧设计的依据。

## 3. 端能力与断点

以 CSS 像素描述视口，不通过 User-Agent 推测手机型号。输入方式、悬停能力、用户偏好与视口分别判断；小窗口桌面也应得到完整可操作的小屏界面。

| 维度 | 手机 `≤720px` | 平板 `721–1023px` | 桌面 `≥1024px` |
| --- | --- | --- | --- |
| 阅读组织 | 单列、就近展开次要信息 | 主内容为先，空间足够才显示辅栏 | 受控阅读宽度、可见作者/目录辅栏 |
| 公共导航 | 有文字的底部主导航；更多底部面板 | 保留紧凑顶部与侧边工具；触摸目标不缩小 | 顶部 logo/搜索与独立右侧 Dock |
| 搜索 | 全屏临时任务，输入与结果各有稳定位置 | 宽度受控的浮层 | Raycast 风格浮层和快捷键 |
| 筛选/选择 | 任务型底部面板，长列表内部滚动 | 弹层或侧面板，按可用空间决定 | 锚定弹层或检查器 |
| 管理 | 单任务标题栏、任务列表、详情编辑 | 可折叠导航，必要时主从布局 | 分组侧栏、表格和检查器 |
| 创作 | 正文为主，属性展开，单一正文视图 | 正文 + 按需属性，避免拥挤双栏 | 宽屏可同时展示正文与属性 |
| 悬停反馈 | 轻触、显式展开、可见选中状态 | 同时支持触摸与指针 | 可增加 hover，但不能成为唯一入口 |

**MUST** 区分全站体验断点和组件内容断点。工作台现有 `≤960px` 导航折叠点、文章属性 `1360px` 检查器分界可以保留：961–1023px 的平板允许已有侧栏，1024–1359px 的桌面也可以按需展开文章属性。不得为追求断点数字一致而压缩真实内容。

**MUST** 在 320px、横屏低高度、字体放大和分屏窗口中仍可完成任务。`pointer: coarse` 的主要按钮、行操作与输入命中区至少 44×44 CSS px；图标本体可更小。此 44px 是 Painter 的触摸目标，严于 WCAG 2.2 AA 2.5.8 通常要求的 24px，二者不能混写。[W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

## 4. 导航分层、URL 与权限

### 4.1 公共浏览层

**MUST** 保持 `/`、`/posts`、`/posts/{id}`、`/moments`、`/moments/{id}`、`/phrases`、`/phrases/{id}`、`/games`、`/users/{id}`、`/search`、`/about` 和启用时的 `/friends` 为共享资源地址，不增加镜像 `/m` 内容体系。

手机底部主导航采用固定数量的高频入口，包含首页、文章、动态及更多；图标配短标签，当前所在的资源类别有明确选中态。片语、游戏墙、账号与页面工具在更多面板按内容/账号/页面分组。发布时以实际导航配置为准，不把全部入口平铺为同等级 Tab。

**MUST** 保持标签只能从搜索及正文上下文进入；About 和友链继续在页脚。主页导航不插入新的营销栏目。**SHOULD** 在更多面板提供账号相关入口；匿名状态明确显示登录，不用一个无解释的头像引导用户反复跳转。

公共顶部依然只有 logo 和搜索。非首页上滑显示、下滑隐藏的规则保留；键盘焦点或模态任务打开时不能把相关操作移出可见范围。手机底部导航与桌面右侧 Dock 不得同时重复占位。

### 4.2 阅读与详情层

从列表进入文章、动态或作者详情属于页面导航。**MUST** 保留原生链接、长按、新标签页与系统分享 URL 的语义。底部导航表示全站去向，目录、日期、点赞、收藏、图片切换属于当前页面任务，不能伪装成全站 Tab。

详情返回优先回到已知的同源来源列表和原来的筛选/位置；无法判断安全来源时使用明确后备地址，如文章返回 `/posts`。不能仅因 `history.length > 1` 就无条件调用 `history.back()`，因为上一页可能是站外页面。

### 4.3 个人与创作层

- **MUST**：`/me` 及收藏、足迹、会话、媒体等维持登录要求；仅在必要动作上引导登录，公开阅读不强制登录
- **MUST**：owner 与 author 才能进入文章、动态创作；author 的范围保持本人，owner 才能管理全站、标签、片语、友链和成员
- **MUST**：手机公共壳不出现在 `/studio` 工作台和专注编辑流程；工作台不叠加公共页脚与右侧工具列
- **MUST**：可选全局创作入口继续受场景设置与角色控制；默认关闭的配置不能因手机版上线而被悄悄开启
- **SHOULD**：手机工作台顶部显示任务名与菜单；详情任务提供返回上级列表的明确入口；长操作名称不挤掉主动作

导航隐藏只优化体验，不授予或撤销权限，所有写入仍由服务器校验角色、资源归属、CSRF 与版本。

## 5. 页面、弹层与返回行为

| 类型 | 示例 | 返回/关闭原则 | 状态归属 |
| --- | --- | --- | --- |
| 页面 | 文章、作者、搜索结果、编辑器 | 标准历史导航；允许直接打开和刷新 | 资源 ID、查询条件在 URL 或服务端 |
| 临时浏览任务 | 全屏搜索、更多导航、目录、图片预览 | 可见关闭按钮、Esc；支持已实现的历史关闭 | 开关和临时输入在当前页面内 |
| 待确认选择 | 标签筛选、发布属性 | 应用才生效；取消恢复进入时状态 | 已应用值与暂存值分开 |
| 不可轻易撤销操作 | 撤回、删除、退出未同步内容 | 显式说明后果并确认；忙时防重入 | 服务器确认决定完成状态 |

**MUST** 对被登记进浏览器历史的弹层做到：Back 先关闭当前一层、Forward 的恢复行为一致、点击关闭不能再留下一个空历史项、跳转结果前清理自己的临时状态。使用命名空间保存 `history.state`，不覆盖其他模块的状态，不捕获无关 `popstate`，不建立循环回退。

**MUST** 如当前实现某个旧弹层尚未整合历史，明确记录缺口；不能通过全局禁止 Back 模拟客户端。浏览器边缘返回、下拉刷新、双指缩放均不拦截。滑动关闭仅可作为补充，所有面板都有文字或有名称的关闭按钮。

**SHOULD** 恢复列表滚动依靠浏览器原生恢复与 BFCache；确需补充时，以 URL + 当前资源 ID 记录有限状态，恢复后不再次跳回页首。筛选改变和页码改变使用可分享 URL，禁止把全部搜索条件只保存在内存。

## 6. 面板、滚动、焦点与软键盘

**MUST** 为底部面板和全屏临时任务提供：可感知的标题、关闭/取消、受控最大高度、一个主要内容滚动区、稳定的动作区。底层页面不可点击且不能穿透滚动；关闭后恢复打开前的滚动位置与触发焦点。弹层之间切换不叠加两层导航或两套遮罩。

模态任务优先采用 `<dialog>.showModal()` 或等效完整实现，不能只有 `position: fixed` 与灰色背景。打开时焦点进入内部，Tab 留在内部，Esc 关闭；复杂说明先聚焦标题，危险操作先聚焦取消，关闭后返回触发点或合理的新位置。[W3C 模态对话框交互](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

**MUST** 避免“整页、面板、列表”三层竖向滚动。长列表由面板内容区滚动，标题与确认区留在面板内；内容不足时不强制占满屏幕。横向滚动仅用于照片、唱片、代码块、宽表格等真实二维内容，不使整个页面横向溢出。

**MUST** 设置支持安全区的 viewport 与 `env(safe-area-inset-*)`：固定底栏在底部安全区以上，正文为底栏实际高度预留空间，面板按钮不压住系统 Home 指示条。全屏任务以动态可视高度为依据，提供旧浏览器回退，不能单靠固定 `100vh`。

**MUST** 软键盘出现后输入框、错误提示和主要确认动作仍可到达；不要为了“像 App”把正文或表单锁死。视觉视口缩小也可能由缩放引起，不能仅凭高度变化就断言键盘已打开；应结合可编辑焦点判断，并保留可用回退。[VisualViewport 接口与浏览器差异](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)

**SHOULD** 登录、编辑器、评论和动态输入时收起与任务无关的公共底部工具；菜单打开不擅自拉起软键盘，用户打开搜索时才优先聚焦搜索输入。表单输入字号至少 16px，保留系统选择、粘贴、自动填充与缩放。

## 7. 搜索与筛选

- **MUST**：手机点击搜索进入全屏 Liquid Glass 搜索任务，顶部输入 + 取消/关闭，中间建议滚动，底部完整搜索入口；触摸状态不展示成排桌面快捷键提示
- **MUST**：桌面保留 Raycast 浮层、Cmd/Ctrl+K 与非编辑区 `/`；手机接入物理键盘后快捷键也可使用，不能抢占编辑器输入
- **MUST**：空查询给出已有的站内入口与真实最近内容；建议失败仍能提交完整搜索，不把网络失败显示成“没有文章”
- **MUST**：中文输入法组合期间不提交或跳转，异步建议仅采用最新查询的结果；点击建议是可访问的真实链接
- **MUST**：全局搜索不放 filter；`/search` 才展示结果筛选，手机入口显示当前选中数，长标签名可换行
- **MUST**：筛选面板区分已应用条件与正在选择的条件；应用统一提交，取消不改变当前结果，清空不立即丢失当前查询上下文
- **MUST**：保留标签 OR 匹配、最多 20 个、按相关性/最近发布排序、作者限定及游标绑定的服务端语义；只读取公开文章
- **SHOULD**：结果页以命中的标题和摘要为主，短屏不强占封面；保留无结果、上游错误、仍有下一页的真实区别，不把当前页数量冒充总量

## 8. 首页、内容列表与阅读

### 首页与收藏墙

**MUST** 保留站长配置的顺序、开关、真实内容与数量。手机首页用自然滚动展示个人介绍、项目、活动、唱片、游戏与阅读入口；允许减少并行层与动画距离，不能把桌面长距离 pin 叙事原封不动缩小。

**MUST** 保留静态背景，不能重新启用已关闭的滚动变色。热力格与唱片的过渡若出现，来源仍是连续、行列一致的中央矩形，不能随机抽取日期格。游戏仍来自唱片网格内独立格，不能替换一个专辑，也不能添加会暗示横向翻页的圆点。

**MUST** 触摸下项目可直接访问或有明确展开操作；不存在只有 hover 才能发现的链接。唱片、照片与游戏有正常流入口；任何吸附不抢滚动、不发生于表单、内部滚动或减少动态模式。

### 列表

文章保持垂直清晰的列表，标题是主要链接。动态手机固定双列，桌面按宽度展示多列，不提供列数切换。列表展示首图与短正文，无额外可见页头；桌面普通点击可展开左图右文阅读层，地址保持真实详情 URL，手机保留正常页面导航、作者栏与原生横向滑图。修饰键、新标签、无 JavaScript 和分享深链始终能直接进入独立详情。游戏墙封面优先、元数据对齐，未知时长不显示成零。片语保持完整句子和出处，不通过固定高度截断。

**MUST** 每一类都覆盖加载、空、失败、分页和内容撤回；当前页计数不得伪装成全库总数。加载更多不重复插入或重排已有结果；分页链接和无 JS 的基本阅读路径保留。

### 文章与详情

**MUST** 手机正文拥有可读的单列宽度；作者身份、订阅/关注在紧凑一行，简介在下；摘要和标签同属文章引导区，封面与正文对齐。时间信息保持 `i` 入口，只展示作者开启的创建、编辑、发布时间。

**SHOULD** 手机将目录做成就近展开的目录面板或清晰折叠区，选择章节后关闭并定位；标题锚点为公共顶部留出可视间距。日期、目录、分享等次要工具不常驻铺满正文。

**MUST** 匿名用户遵守现有互动显示策略，不能因移动布局恢复未授权点赞/收藏操作。评论的加载、登录、错误、撤回状态与文章本体分区，推荐有独立标题和表面，不以三种相同横线混淆文章分隔、评论区与推荐区。

图片预览保持暗蒙层、完整未裁切图片、关闭及前后切换，无装饰相框。原图链接、键盘、辅助技术和失败回退可用；如增加滑动切图，不能夺走双指缩放与页面系统返回。外链卡和动态/片语引用保持各自资源权限与新鲜读取规则，不能把预览缓存当作公开授权。

## 9. 手机创作与后台任务

### 文章创作

**MUST** 文章编辑为独立任务：紧凑返回、保存状态、文章信息/发布入口；正文是主要区域，格式工具与当前正文同一视觉边线。文档编辑默认，源码从更多进入；两种表示共享同一个标题、摘要、标签、封面和日期设置，不创建两个草稿。

**MUST** 手机不并排展示源码和预览，不同时打开全部属性。文章属性可展开为一个连续检查区或完整面板，发布是明确动作；改变编辑表示不应发布、重置属性或丢失选择。键盘打开时正文可继续滚动，工具按钮不覆盖输入光标。

**MUST** 保留 IME 组合输入、只读锁、初始化失败重试、上传队列、CAS 冲突与修订恢复的现有保护。修改正文前不重写未改动 Markdown；遇不支持语法，告知并完整保留源码，而不是静默降级丢内容。

| 状态 | 必须告诉用户什么 | 允许的下一步 |
| --- | --- | --- |
| 尚未确认服务端保存 | 有修改 / 正在保存 | 继续写、等待、导出 |
| 服务端确认当前序列 | 已保存 | 离开、继续写、主动发布 |
| 离线或网络失败 | 本地修改已保留；未同步到服务器 | 继续写、恢复网络、导出 |
| 本地存储也失败 | 无法建立恢复点，存在丢失风险 | 明确导出，不显示“已保留”保证 |
| 版本冲突 | 本地与服务器各自内容，自动保存已暂停 | 读取最新、比较、明确选择后手动保存 |
| 修订恢复确认失败 | 当前内容仍保留，尚未确认恢复结果 | 只读重查或导出，不盲目重放恢复命令 |

现有文章编辑器变更后约 250ms 写本地恢复点、约 1000ms 尝试自动保存；这些是调度延时，不是持久化完成时限。恢复键包含 origin、用户和文章或 client draft ID；同一账号重进时先核对服务器映射和版本。**MUST** 只有相应写入实际成功才显示本地或服务器保证。

**MUST** 不承诺手机浏览器退后台、强杀、切网后仍能完成网络保存；尽早持久化并在恢复前台重查。`beforeunload` 只是一层提示，不能成为唯一保护；退出账号前说明并清理该账号恢复点，不把上一个账号未发布内容展示给另一个账号。

### 管理与其他编辑

**MUST** 手机文章管理优先显示标题、状态、更新时间、编辑与更多；通过行内标签或紧凑任务行完成高频操作。宽表只用于确有比较价值的列，其横滚局限容器，操作不能永远藏在最右侧。

**MUST** 标签、友链、片语等一次只编辑一项；保存、取消与所属对象相邻。服务端失败保留输入；切对象、撤回和删除确认只在确实会丢失或改变公开内容时出现，不为普通导航堆确认框。

动态保留 500 码点/九图、逐张上传、草稿与发布分离。**MUST** 区分其尚无文章级持久离线恢复与修订历史的事实；不能因共用手机表面就显示同等恢复承诺。照片失败可重试，已成功项不能跟随失败项全部清空。

**SHOULD** 长设置按网站信息/功能与通知/登录安全等既有任务分组；当前分组有名称与 URL hash。手机可分段选择但不每换分组就卸载、丢弃尚未保存的表单。登录应用表等精确数据可局部横滚，并仅在确有溢出时给出提示。

## 10. 登录、2FA 与通用身份

**MUST** 所有端遵守服务器注册/外部登录开关，owner 的维护入口保持可用；不在手机重新提供已关闭注册入口。登录回跳限同源安全地址，账号密码交给密码管理器和标准自动填充。

**MUST** 已启用 MFA 的账号先验证密码或 GitHub、再显示动态码/恢复码任务，第一步成功不代表完整登录。动态码采用适合数字输入的键盘并允许一次性验证码自动填充；恢复码采用可粘贴的文本输入，不强制数字、不禁粘贴。错误和锁定有明确文本，重复点击不得产生并行验证。

**MUST** 绑定验证器同时提供本地生成二维码和可复制的手动密钥，手机单设备可通过复制密钥完成配置。十个恢复码只在生成时完整展示，下载/复制后有明确保管提示；未保存离开有提醒。密钥、二维码、恢复码、客户端 secret 不进入埋点、URL、日志、Git 或持久草稿。

**MUST** 浏览器权限、相机、文件选择使用真实平台能力与拒绝回退；不能仿制系统弹窗。本站手机号/邮箱资料不因此变成已验证登录身份，不提供未实现的短信、邮件或 Passkey 流程。

OIDC 接入、会话撤销、恢复限制详见 [账号安全](ACCOUNT_SECURITY.md) 与 [身份服务](IDENTITY_PROVIDER.md)。手机 UI 不另建一套 MFA 密钥或认证库。

## 11. 视觉、动效与无障碍底线

| 项目 | MUST | SHOULD |
| --- | --- | --- |
| 层级 | 一个主要任务、一个清楚的主要动作；标题/内容/动作共用对齐线 | 手机边距以 16–20px 为基准，避免嵌套面板多次缩进 |
| 材质 | 导航/搜索遵守既有玻璃，工作区使用实色；降低透明度时文字仍可读 | 避免大面积叠加多重 blur，较弱设备可退回实色 |
| 控件 | 共用 item/control/menu/surface 半径 token；触摸目标44px | 字号、按钮视觉密度与桌面分别设置，不能靠放大所有圆角表达手机化 |
| 链接 | 正文与明确阅读动作可用苹果蓝；导航/结构链接保持中性色与清晰状态 | 通过下划线或动作文案补足只靠颜色的识别 |
| 字体与对比 | 两种主题、系统高对比/forced-colors、200%缩放仍可阅读；不禁缩放 | 正文行高约1.8，长中英标题换行，代码自有滚动区 |
| 动效 | `prefers-reduced-motion` 下无吸附、强视差或持续循环；内容始终可访问 | 菜单约160–220ms，任务转场不等待冗长动画 |
| 反馈 | 写入成功由服务器确认；失败在任务位置显示，忙状态防重入 | 普通成功短状态提示，重要错误不只闪现 toast |

**MUST** 使用正确的 `a`、`button`、`label`、`fieldset`、标题层级与 `aria-current` / `aria-expanded` / `aria-pressed`；图标有名称，不能只凭 tooltip。搜索建议继续 combobox/listbox 语义，真实链接支持原生激活；不要为任意按钮组滥用 `role=menu`。

**MUST** 动态结果和保存状态合理使用 `role=status`，阻断错误使用 `role=alert`，避免每个字符或每次滚动都被播报。自定义选择器保留键盘、选中、禁用、焦点和 Escape；文件/日期仍可用设备原生选择，不为了统一外观破坏平台能力。

## 12. 性能、数据与未来客户端

**MUST** 公开文章 SSR 保留首屏正文与可索引语义；不能为手机壳把阅读改成必须加载大型应用才能看到的空页。手机导航增强失败时原生链接仍可用，搜索有普通 `/search` 入口，禁用脚本仍可读公开正文。

**MUST** 内容媒体保持尺寸约束、防布局跳动；首屏外图片延迟加载，首屏关键图片不能一律延迟。已有图片服务尚无通用多尺寸变换时，不伪造 `srcset` 能力；新增时按真实变体与裁切验证。游客请求不触发 Steam/Apple Music/GitHub 实时同步。

**MUST** 滚动用原生行为与被动监听，动画合并到单个待执行帧；离开视口和静态模式不运行空闲循环。导航、目录、设置操作不依赖 3D、GPU 或外部动画服务。埋点记录任务事件与结果，不记录正文、搜索原文、密码、OTP 或恢复码；遵循浏览器统计开关。

后续原生客户端共享的是资源 ID、分页、公开/草稿界限、CAS/幂等错误合同与身份协议，不直接嵌入桌面管理 DOM 当成跨端架构。

- **MUST**：原生登录使用外部系统浏览器、OIDC Authorization Code + PKCE S256、登记回调与 `state` / `nonce`；不得在 App 内收取 Painter 密码或嵌入保密客户端 secret。[RFC 8252](https://www.rfc-editor.org/rfc/rfc8252)
- **MUST**：令牌按平台安全存储能力保存；网页 Cookie 与客户端令牌属于不同凭据边界，不把 Web localStorage 当作原生 Keychain/Keystore 的替代
- **MUST**：当前 OIDC 的 `openid profile offline_access` 提供身份，不授予 Painter 文章编辑、管理或任意 API 的 bearer 权限；本地工作台仍使用同源 Cookie + CSRF。未来客户端业务权限、令牌 audience/scope、撤销与服务端检查须单独实现后才能发布相关客户端功能
- **SHOULD**：深链统一映射现有文章、动态、作者地址，App 未安装时回退 HTTPS 页面；分享仍以公开资源权限为准
- **后续能力**：PWA 离线阅读、推送、后台上传、Device Flow、Passkey、原生分享、独立应用导航栈与发布分发，均需另行实现和验收，不由本规范自动启用

## 13. 实现顺序与验收矩阵

实施顺序：公共手机导航/更多 → 搜索任务与筛选 → 文章阅读/首页触摸 → 工作台/编辑器 → 两主题与异常状态。单独完成的功能分批验证和 commit，不把只完成样式宽度适配当作交互验收。

V44的源码落地点为公共四项底栏、更多sheet、全屏搜索、暂存后显式应用/取消的筛选、自然流手机首页、手机工作台任务壳和编辑器正文/文章信息两步骤。个人设置增加资料/主页/安全，站点登录安全增加访问控制/GitHub/应用接入，切换保留挂载表单。共享`mobileOverlays.ts`负责已登记dialog的临时历史与可视视口；这些代码仍需按下表逐项验证，尤其不能仅凭实现存在就宣布Back/Forward、Enter提交或真实软键盘已通过。

## 14. 维护规则

以后新增页面先标注任务类型（体验/阅读/操作）、适用端、主动作、返回层级和异常状态，再选择共享组件。修改本规范时同步对应实现和验收编号；只补充实际业务，不为“全端一致”创造未实现能力。视觉 token 与具体表面方向仍由源码、`web/DESIGN.md` 和当前页面实现 管理，本文件负责跨端交互约束。
