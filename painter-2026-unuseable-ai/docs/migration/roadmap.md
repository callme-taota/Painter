# 迁移与灰度路线（create-migration-roadmap）

## Phase 0：现网止血（1-2 周）

- 修复接口 method 与字段契约错误
- 修复明显 correctness 问题（中间件流程、查询条件错误）
- 增加 traceId 与核心指标埋点

## Phase 1：契约统一（2-4 周）

- 完成 OpenAPI v1 首版，冻结旧接口新增
- 前端逐步切换到 SDK 调用
- 建立接口变更评审与 CI 校验

## Phase 2：后端分域（4-8 周）

- 先按模块拆分代码边界，再拆部署边界
- content 与 identity 先独立服务化
- gateway 引入路由级灰度能力

## Phase 3：前端模块化与性能（3-6 周）

- web/admin 双应用完善
- 高频页面完成虚拟化与缓存治理
- 配置中心与前端动态能力打通

## Phase 4：灰度切流与收口（2-4 周）

- 按接口与用户分组灰度切流
- 双写校验 + 回放比对
- 全量切换后下线旧链路

## 回滚机制

- 路由级回滚：gateway 一键回切旧服务
- 数据回滚：关键表保留迁移前快照，双写阶段可反向对账
- 配置回滚：配置中心支持版本回退

## 验收门槛

- 核心路径 P95 持续稳定，错误率低于目标阈值
- 契约一致性由 OpenAPI/SDK 保证
- 配置化覆盖率达到预期
