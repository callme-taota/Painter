# 数据与渲染性能方案（design-data-and-performance）

## 数据读取效率策略

- 列表查询改为聚合 SQL，避免 N+1。
- 热点数据（配置、标签、分类）采用 Redis TTL 缓存 + 主动失效。
- 读写分离预留：读流量可切只读副本。
- 评论与互动表按高频查询字段建立复合索引。

## 后端性能目标

- 关键链路（登录、文章列表、文章详情）P95 < 200ms（内网条件）。
- 缓存命中率目标：配置类 > 95%，字典类 > 90%。
- 慢 SQL 统一采集并分级告警。

## 前端渲染策略

- 使用 query 缓存层，统一 staleTime 与重试策略。
- 文章列表/评论使用虚拟列表组件，降低节点数。
- Markdown 预览采用防抖，必要时 worker 化。
- 滚动与 resize 监听统一节流，并在卸载时清理。

## 观测与压测

- 指标：QPS、P95/P99、error rate、cache hit ratio、DB connection usage。
- 压测脚本按域拆分，网关聚合报告。
