# 1:1 复刻差异与修复记录

## 说明

本项目采用“修复优先”策略：尽量保持旧行为一致，但已知错误会规范化修复。

## 当前差异

1. **设置接口方法规范化**
   - 旧：`POST /api/setting/`
   - 新：主契约为 `PATCH /api/v1/system/admin/settings`
   - 兼容层保留旧 POST 路径并转发为 PATCH。

2. **统一响应协议**
   - 旧接口存在多种返回结构。
   - 新统一为 `{ code, message, traceId, data }`。

3. **接口域重构**
   - 旧接口以业务资源散列在 `/api/*`。
   - 新接口聚合到 `/api/v1/{identity|content|system|analytics}/*`。
   - 网关提供 `/api/*` 兼容层保证旧客户端可访问。

## 验收要求

- 旧路径存在并可调用（映射或兼容层）。
- 新路径契约完整，SDK 可用。
- 修复项必须有测试或至少回归检查记录。
