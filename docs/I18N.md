# 界面国际化

首版支持 `zh-CN`（简体中文）和 `en`（English）。公开页面、工作台、编辑器、登录、提示与错误使用同一套消息词典。文章、动态、片语、标签名称、昵称、产品介绍和站点自行配置的文字保留原文；本功能不自动生成内容译文。

## 语言选择

公开页面在「更多 → 语言」切换；后台在侧栏底部切换。使用普通页面导航，保留当前路径、搜索条件和锚点，继续执行浏览器原有的未保存内容离开检查。

服务端按以下顺序解析：有效的 `?lang=`、保存的 `painter_locale` Cookie、带权重的 `Accept-Language`、简体中文。显式页面参数也会保存偏好。语言 Cookie 不包含账号信息，使用 HttpOnly、SameSite=Lax，在 HTTPS 下设置 Secure。内网地址与外网域名各自保存偏好。

`GET /locale?lang=en&next=/products` 保存语言并返回当前站内页面。`next` 仅接受安全的站内相对地址，拒绝跨域、协议相对地址、反斜线和控制字符。无 JavaScript 时仍能切换，锚点保留由客户端增强。

SSR 在发送 HTML 前决定语言，输出相应的 `html[lang]`、`Content-Language` 和缓存变化信息。前端读取 `html.lang`，不通过扫描或替换 DOM 翻译页面。API 请求携带当前语言，业务字段、错误码、权限与幂等语义保持不变。

## 消息与格式

共用词典位于 `web/locales/en.json`，由 Go 嵌入和前端构建共同读取。中文原消息作为消息 ID；遗漏的条目回退到原消息。代码中的业务 enum、URL、Markdown 围栏与卡片类型不可作为翻译内容。中文页面不加载英文词典；英文按需载入并缓存独立静态资源，加载失败时回退原消息，刷新可重试。

前端使用 `t('移除标签：{name}', {name})`；SSR 使用 `{{t "关于 {name}" "name" .Name}}`。动态语句应写成整句，并使用命名占位符。插值只进行一次，值中的花括号不会成为新模板；展示仍由 Vue、Go HTML 模板或 `textContent` 转义，不允许把译文作为任意 HTML 执行。

服务端静态错误继续使用 `E`，动态错误使用 `ET(400, "VALIDATION_FAILED", "事件缺少属性 {name}", "name", key)`。错误只在响应出口本地化，日志和已有调用方得到原中文消息；普通参数不进行翻译。验证器拥有的嵌套原因通过显式 `translatableMessage` 标记，不能将用户输入标记为 UI 消息。

日期与数字使用当前语言的格式。界面日期默认采用 `Asia/Shanghai`，与服务端及既有发布时间口径一致；前端调用方可显式指定其他时区。API 时间戳和统计时区不因语言切换而改变。数量提示优先用完整、中性的句式，避免拼接出 `1 articles`。

## 内容、SEO 与应用

界面语言不会产生文章的不同语言版本，规范 URL 继续指向同一内容。语言偏好入口不是内容译本，不输出虚假的 `hreflang` 对应关系。将来提供人工维护的正文译本时，应单独建立内容关联与规范 URL 规则。

PWA 清单的语言和快捷入口跟随界面，站点名称、安装 ID、scope 和 start URL 保持稳定；不会因为切换语言创建第二个应用。

## 扩展与验证

新增语言需要注册服务端及前端支持的 locale，提供同结构词典，并补充语言入口和格式测试。新增文案应走 `t`、SSR `t` 或 `ET`；不得翻译保存到数据库的既有用户内容。复杂复数或 RTL 语言加入前，还需实现其复数规则、方向和对应布局验证。

检查包括中文回归、英文首屏与后台、带查询与锚点的切换、日期边界、占位符转义、错误契约、正文/卡片保存、手机与桌面布局。数据库集成验证只使用显式的可丢弃 PostgreSQL 18 测试库。
