# 个人中心与请求审计 V49

范围：2026-11-14，`/me`、公开用户页的关注增强、文章互动增强，以及前端通用请求入口。本文记录实际源码路径和本轮改变；不代表对全站所有接口、SQL 或外部服务完成性能审计。公开用户页、专栏、分享和部署的最终验收以 V49 发布记录为准。

## 1. 普通读者原来的体验问题

`App.vue` 原来把个人资料、作者背景和账号安全放在同一页。手机仅用 `v-show` 隐藏分区，组件仍会挂载；桌面同时展示三个区域。因此普通 reader 打开 `/me` 也会发出作者背景与安全设置请求，页面却缺少收藏、关注、足迹这些主要阅读任务。

个人中心与公开主页是两个不同地址：

| 地址 | 访问者与内容 | 隐私边界 |
| --- | --- | --- |
| `/me` | 只有本人；阅读入口、资料编辑、主页外观、账号安全 | 邮箱、电话、收藏、足迹、会话不在公开页展示 |
| `/users/{id}` | 访客可访问；昵称、头像、公开简介、自定义背景 | 不把个人中心数据直接交给公开模板；读者不被当作拥有空文章列表的作者 |
| `/studio/posts` 等 | author / owner 的创作与管理任务 | 导航筛选不替代服务端角色和资源归属校验 |

本轮个人中心采用同一组任务标签：**我的 / 资料 / 公开主页 / 安全**。默认展示收藏、关注、足迹；只有创作者显示管理文章和写新文章。手机和桌面保持一致的信息边界，版面按各自宽度调整。

- 默认仅加载登录状态与本人资料，不挂载主页背景或安全组件
- 首次打开“公开主页”才读取背景，首次打开“安全”才读取两步验证状态
- 切回任务时保留已挂载组件，避免丢失未保存资料、验证码绑定状态和只显示一次的恢复码
- 资料保存失败时保留表单，400 可以直接纠正；409 重新读取需要明确确认，取消继续保留未保存输入。初次读取失败仍有重新加载入口。
- 支持直接打开 `/me#profile`、`/me#appearance`、`/me#account-security-title`
- “公开主页”文案适用于普通读者，不再把所有人称作作者

## 2. 实际发现与处理

| 位置 | 原请求行为 | 本轮处理 |
| --- | --- | --- |
| `api.loadSession`、`postLike.loadLike`、`FollowIsland`、`PostIsland` | 每个调用者各自读取 `/session`，同页可重复 | 共用独立 `publicSession.ts`；公共点赞模块不为此加载 Vue |
| `publicSession.ts` | 原来没有独立状态读取边界 | 合并正在进行的请求，成功结果只在当前文档内存保存 60 秒；不写入浏览器存储 |
| `api()` 默认 GET | 多个组件同时请求同一路径会分别发送 | 只合并无额外 Fetch 选项的同路径在途 GET，完成或失败立即移除；成功写入后清除在途协调记录，写后读取不会加入写前读取；没有通用成功数据缓存 |
| 带 `AbortSignal`、自定义 headers / cache 等的请求 | 各自拥有取消和读取语义 | 继续独立请求，不错误共享取消，也不合并写操作 |
| `postLike.ts` | 永久保留首次加载 Promise，失败后也不再重试 | 在途 Promise 结束后移除；成功状态有 60 秒时限；失败可以重试 |
| 文章浮动点赞与正文互动 | 分别取得 liked / bookmarked，重复查询 `/me/post-states` | 一次关系响应同时得到点赞和收藏；共享状态与更新事件 |
| `FollowIsland` | 为判断一个人是否关注，遍历 `/me/following` 的所有分页，并另查 `/site` | 改为单次 `GET /users/{id}/follow-state`，返回本人对该用户的关注状态和关注开关 |
| `/me` | 初次就挂载主页和两步验证 | 按实际任务首次挂载，之后保留组件状态 |
| `/studio/settings` | “网站信息”打开时，隐藏的安全区域仍挂载身份客户端等组件 | 安全区进入后才挂载；手机 GitHub 和应用接入首次进入才挂载，之后保留实例，不因任务切换或断点变化丢失表单 / 一次性 Client Secret |
| 评论分页 | 连点可能重入，失败没有就近恢复入口 | 分页独立忙碌状态和错误反馈；提供重新载入讨论 |

### 缓存、认证与并发边界

会话成功缓存不是授权凭据；每次服务端写入仍校验会话、角色、CSRF、归属和版本。缓存只降低重复读取，不放宽后端授权。

- 退出登录、401、本人资料更新和 MFA 写入后使共享会话失效
- 会话轮换后重新读取最新 CSRF，不复用旧值；软失效中的旧 Promise 会重新验证，避免把正常轮换错误呈现为退出登录
- BFCache 恢复失效；切到后台使有效期到期，下次读取重新验证
- 失败不保存为成功缓存，不把请求失败伪装为匿名成功
- 正在进行的旧会话响应不能在退出后恢复原账号
- 主动退出在清身份前停止编辑器后续持久化，等待已有恢复点写入完成，再由退出流程清理原账号恢复点
- 会话过期与主动退出分开：过期先把最新未保存内容保存到稳定的原账号命名空间，再清身份；工作台跳转保留原 path / query / hash，公开阅读不自动跳登录
- 并发 401 共享一次过期流程；恢复点收尾不等待正在报 401 的保存队列，避免相互等待；主动退出期间的其他 401 不抢先触发登录跳转
- 旧账号的点赞 / 收藏响应不能覆盖后续账号的状态
- 私人关系数据没有跨文档或持久化缓存；当前文档内最多缓存 60 秒

`AuthForm` 登录、MFA 验证与密码修改完成后原本就执行完整页面跳转，因此新的文档使用全新模块内存。未引入 localStorage 会话缓存、Service Worker API 缓存或跨账号共享缓存。

## 3. 哪些请求应保留

请求数量应按任务判断，而不是简单把所有接口合成一个大接口。

- **文章正文、目录、作者、推荐**继续由 Go SSR 提供，不在首屏再次请求整篇文章
- **评论**按接近评论区时加载，分页有独立游标；匿名仍可按现行规则查看公开讨论
- **个人互动状态**需要会话和私有关系查询；不混入可公开缓存的文章正文
- **点赞后的 metrics**保留，用服务器聚合值校准多人并发下的总数；不能只用本地加减当作权威总数
- **站点功能开关**在讨论进入时仍读取 `/site`；本轮没有把全部站点设置注入 SSR 或长缓存
- **搜索建议**维持输入防抖、旧请求取消和最新序列校验；不同查询不能错误合并
- **编辑器自动保存、预览和封面预览**分别对应持久化、服务端安全渲染和图像产出，职责应该分开，CAS / 幂等 / AbortSignal 应保留；但当前预览触发条件仍有冗余，不能据此认为每次请求都必要
- **分页**保留真实游标，不为减少请求而预取完整关注、文章或媒体库
- **文章内动态 / 片语引用**仍按公开权限和即时状态解析，不能使用跨渲染成功缓存保留已撤回内容

已登录文章在正文互动进入、且同一 60 秒窗口内，相关读取是登录状态、点赞计数、文章关系、站点开关、评论首批。当前文章模板不挂载关注组件，真实候选录制为 5 个相关 GET；公开个人页的关注组件另有 1 个 follow-state 读取。该数不含资源文件、埋点、卡片提供方或用户主动操作；登录失效、超过 60 秒或未进入评论区时数量会不同，不能当作全站固定请求总数。

普通 `/me` 默认任务预算是 `/session` 与 `/me` 两个读取；打开其他任务后才增加相应业务请求。

## 4. 后续交互优先级

| 优先级 | 下一步 | 原因与验收方向 |
| --- | --- | --- |
| 高 | 编辑器仅按需渲染可见预览 | `changed()` 在文档模式、纯源码编辑，以及只改标题 / 标签时也调度 Markdown 预览；应按 Markdown 变更且预览可见触发，进入预览再补最新版本，不能改动保存 / 发布安全检查 |
| 高 | 大表格行操作与单行忙碌态 | 现在若沿用页面级 busy，会阻塞不相关记录；应只锁定正在更新的资源，并保留 CAS 冲突反馈 |
| 高 | 已保存状态与离开保护统一 | 个人资料、主页、专栏等表单需要同一套未保存反馈；切换标签保留状态，真正离开时才确认 |
| 高 | 列表失败重试与空状态分开 | 网络错误不能显示为“没有内容”；重试应留在原筛选和分页位置 |
| 中 | 普通读者与创作者的导航用词 | 个人中心以阅读为主，创作角色增加任务；公共页关注对象不必叫“作者” |
| 中 | 评论、收藏、关注的就近反馈 | 同一资源反馈一致；成功不弹阻断对话框，错误可就近重试 |
| 中 | 动态 / 片语引用批量读取 | 同一编辑预览包含多个引用时可考虑 bounded batch，但必须继续做逐条公开权限与撤回检查 |
| 中 | SSR 下发最少公开功能开关 | 可进一步消除 `/site`，需定义公开 DTO，避免把管理设置或私人资料一并嵌入 HTML |
| 后续 | 真实流量下的慢查询与请求瀑布 | 先记录路由、耗时、状态和查询量，定位 N+1；不用前端组件数量推断服务器瓶颈 |

本轮不引入全站 GraphQL、BFF 大改、通用无限缓存或整页预取。专栏和三层分享的服务端事务、公开读取和权限边界应由各自模块负责。

## 7. 会话结束与本地恢复点回归

真实隔离探测发现，即时清空共享 session 会使编辑器卸载时的恢复键出现 `undefined` 账号：原账号恢复点已清理，但新产生的无账号记录仍留在浏览器。已增加稳定的编辑器 actor ID 和会话结束收尾接口：

- 主动退出：先停止该编辑器的定时保存 / 本地持久化，等待所有已开始的 IndexedDB 写入，再清 session 与原账号恢复点
- 意外过期：锁定编辑器、保存最新可序列化快照并等待本地写入，再清身份、发出一次过期通知；保留草稿供同账号登录恢复
- 工作台统一响应过期，返回地址使用当前真实 pathname / query / hash；匿名公开页面不被强制跳登录

请求协调测试新增退出等待、失败退出不停止本地保存、并发 401 去重和退出期间 401 不抢跳，现共 54 个断言。真实 `tests/browser/v49-logout-recovery.cjs` 已在最终候选通过 23 个断言，覆盖正常退出、延迟 IndexedDB 写入退出、意外过期保留未保存快照三个场景：两种主动退出均等待已开始的写入后清空本地恢复记录，没有无账号键；真实保存请求收到 401 后，最新未保存标题保存在原账号恢复点，完成本地写入后才跳登录，`return_to` 保留原路径、查询与 hash。合成文章均为隔离测试库内的未发布草稿，报告位于忽略目录 `tests/artifacts/v49/logout-recovery/report.json`。

最终候选同时重跑个人中心的 79 个断言通过。此次只修复会话结束时本轮引入的回归，编辑器可见预览优化仍留作独立迭代。

## 8. 文章页真实请求录制

在同一隔离候选服务，以 reader 登录访问已有公开文章并滚动至讨论区，实测相关业务 GET 为 5 次：`/session`、`/posts/{id}/metrics`、`/me/post-states`、`/site`、`/posts/{id}/comments` 各一次。当前文章模板不挂载关注组件，公开个人页的 `follow-state` 是另一场景。正文没有再请求 `/posts/{id}`，没有扫描 `/me/following`。该样本不包含图片 / 封面资源、埋点或主动交互，不代表所有文章恒定 5 次；外链卡片与开关会改变网络记录。原始路径记录在忽略目录 `tests/artifacts/v49/article-requests.json`。
