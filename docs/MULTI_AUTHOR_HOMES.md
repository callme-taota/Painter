# 多作者平台与个人主页

2026-11-15。本站开始支持朋友共同发布，先把「找内容」与「认识一个人」分开，保留现有个人展示。

## 本轮已经实现

| 入口 | 内容范围 | 展示方式 |
| --- | --- | --- |
| `/discover` 站内 | 所有作者当前公开的内容 | 最新文章流、真实创作者入口、少量专栏 |
| `/users/{id}` 个人主页 | 该用户本人 | 背景、头像、名字、简介、关注；创作者有文章 / 动态 / 专栏切换 |
| `/posts`、`/moments`、`/series` | 全站对应类型 | 原有完整列表和连续加载 |
| `/` 原视差展示 | 现有站长单例配置 | 本轮保留；尚未迁移为每人的独立视差首页 |

站内从桌面「浏览」和手机底栏进入；个人页可以返回站内。不增加常驻浮动按钮。原有文章 URL、作者稳定 URL、分享及登录机制不变。

站内文章直接显示真实标题、已有摘要、可选封面、作者、作者允许展示的日期和最多两个标签。按首次发布时间排序，编辑旧文不刷新发布排名。未建立热度或编辑精选模型，不把最新文章称为热门或精选。

创作者入口最多八人，来自确有公开文章、动态或专栏的有效创作者。仅有账号、草稿或私人收藏不会进入目录。专栏按原有创建顺序展示，不宣称按最新章节排序。

个人页的搜索只查本人文章。动态、专栏原生链接切换会清空旧搜索与游标。普通读者看到公开资料页，其收藏、足迹、联系方式不公开；不会出现空的创作者栏目。

## 邀请朋友发布

1. 按当前注册开关创建账号；普通注册默认是读者。
2. 站长在后台「成员」中把需要发布内容的朋友设为创作者 `author`。
3. 朋友从自己的工作台发布文章、动态或专栏。公开后自动进入站内入口，自己的主页只显示自己的内容。
4. 草稿、撤回、删除不进入公开列表；作者不能编辑他人内容。站长保留全站治理权限。

禁用账号沿用原有语义：停止登录和写入，不自动删除已经公开的正文；需要撤下内容时显式撤回。目录不再推荐已禁用账号。

## 页面与数据链路

公开页面使用 Go SSR，不靠浏览器逐条请求作者资料。`communityPage` 读取公开快照：文章每批 12 篇、专栏最多 3 个、创作者最多 8 位；渲染阶段不会访问 Steam、PSN、Apple Music 或 GitHub。

个人入口先验证路由用户存在且主页可见，再把路由用户 ID 绑定到内容查询。`authorContentQuery` 只保留当前栏目允许的参数；传入的 `author_id`、`scope`、`status` 不能覆盖归属。分页复用内容域的签名游标，绑定作者及筛选，不能把别人的游标或另一种内容的游标拼进来。查询与游标错误保留身份区域并提供重试。

个人文章、动态、专栏使用各自 canonical；搜索和游标页禁止索引。站内入口加入 sitemap。栏目、按钮和空态支持现有中文 / 英文，作者姓名、简介、标题与正文保持原文。

本轮不改数据库结构，也不改任何写入权限。

## 首页最终应如何协调

建议最终把根地址作为站内内容入口，每位创作者有自己的个人主页。现在的视差名片、项目、唱片和游戏展示保留在站长的个人主页内；朋友可以选择简洁主页，不要求每个人都有收藏墙。

这一步涉及现有首页归属，和本轮已经完成的公共入口分开处理。根地址暂保留原行为；也可以继续以个人根首页为主，并长期使用 `/discover` 承接全站内容。

当前首页文章和发布日历统计全站，而介绍及收藏墙来自站长单例。它还不能直接挂到每位用户下面，否则会把朋友的发布记录归到站长、把站长的收藏归到朋友。原首页的全站统计不代表该用户的个人统计。

## 完整个人展示的后续迁移边界

现有 `homepage_settings`、`homepage_items`、`homepage_projects`、`homepage_music_playlist`、`homepage_game_connections` 没有用户归属。产品和片语也仍是站长管理的资源。不能仅给 URL 加一个用户 ID，或者放开后台权限。

迁移需要一次完整的归属闭环：

- 新的个人配置以 `user_id` 唯一关联；图片、音乐、游戏、项目、歌单、连接及同步任务都绑定同一个用户。
- 原单例保留备份，通过明确的目标用户 ID 认领；先预览条目数与引用，再事务迁移。不能根据昵称、当前文章作者、媒体上传者或最早管理员自动猜归属。
- 保留原条目和媒体 ID、来源引用、凭据密文。新作者得到自己的空展示库，不继承站长收藏或 API Key / PSN 凭据。
- 同步的替换、删除、upsert、唯一键、锁、租约、失败重试及版本校验必须限定用户；加入每用户配额和任务并发限制，避免一个账号占满服务。
- 图片授权必须匹配同一用户的可见主页；不能继续通过站点单例的可见设置公开所有人的媒体。
- 个人最新文章和热力图明确绑定该用户；站内统计保留独立定义。停用账号同时停止其同步任务。
- 视差脚本使用明确的个人展示能力标识；站内列表不启用磁吸，手机继续自然文档流。

`/users/{id}` 继续作为稳定地址。用户名允许修改，若增加 `/@用户名`，先做别名重定向并建立旧名保留策略，不替换稳定地址。

后续可增加人工精选、关注内容流和最近章节更新。关注流需要服务端过滤及绑定当前读者的签名游标，不能前端获取全部关注用户再拼接。
