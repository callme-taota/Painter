# 动态图片与卡片展示规范

适用范围：动态列表、作者页的动态卡片，以及它们打开的公开详情。桌面多列、手机双列使用相同分档，横图上限分别控制。

## 列表预览

图片铺满各自的圆角卡片，不加内边距、相框、补色条，不拉伸。**不再将所有图片统一裁成 4:5**。以浏览器最终显示方向的宽高比 `r = 宽 / 高` 分档：

| 原图范围 | 桌面展示比例 | 手机展示比例 | 取景规则 |
| --- | --- | --- | --- |
| `r < 0.5`，超长竖图 / 长截图 | 2:3 | 2:3 | 顶部居中，先看开头 |
| `0.5 ≤ r < 0.9`，普通竖图 | 保留原比例，最低为 2:3 | 同桌面 | 居中；只有低于 2:3 的图片裁掉上下 |
| `0.9 ≤ r ≤ 1.1`，接近方形 | 1:1 | 1:1 | 居中，少量裁切 |
| `1.1 < r ≤ 2`，横图 | 保留原比例 | 保留原比例，最宽为 8:5 | 居中；手机只裁超出上限的左右边缘 |
| `r > 2`，超宽图 / 全景 | 2:1 | 8:5 | 居中，限制过矮卡片 |

例如：4:5、3:4 竖图完整铺满；9:16 竖图居中保留约 84% 高度；方图完整展示；3:2 横图两端均完整；16:9 横图桌面完整、手机保留约 90% 宽度；3:1 全景桌面保留约 67% 宽度、手机约 53%；1:3 长图从顶部展示约 50% 高度。裁切仅影响列表预览，原文件不变。

- 首图决定卡片比例。列表只加载首图，其他图片通过张数提示，在详情中按原顺序展示。
- 服务器渲染时为首图预留对应比例，图片加载后不重新改变卡片高度。JPEG 按 EXIF 旋转后的方向判断，不能直接用文件原始宽高。
- 既有媒体没有数据库尺寸字段：只为已公开首图批量查一次媒体元信息，本地读取最多 256 KiB 的图片头；使用最多 512 条进程内缓存，不解码整图、不增加浏览器尺寸请求、不改数据库或原 JSON API。缺失、损坏、头部超限或方向无法判断时保持 4:5 占位与居中裁切，不在加载后突然换形状。
- 桌面多列、手机双列，按发布时间的 DOM 顺序逐个放入当前最短列，不将后面的卡片倒填到前面。布局只在容器宽度、文字尺寸或新增卡片时计算；追加内容不会重新分栏挪动已有卡片，滚动不参与计算。
- 无 JavaScript 或不支持尺寸观察时保留同样的图片比例和普通网格列表；首次启用错落排布有一次布局增强，不承诺整页零位移。

缩放系数为 `max(容器宽 / 原图宽, 容器高 / 原图高)`。普通图将多出的部分两侧均分；超长竖图纵向从顶部开始。颜色采样使用**当前端实际展示比例**的同一裁切区域。

## 底部材质与颜色扩散

- 图片始终是主体。文字在图片底部，竖图与方图桌面最多三行、手机最多两行，横图均最多一行，完整正文在详情阅读。
- 文字下方使用局部毛玻璃，竖图和方图覆盖底部约 44%，横图约 58%，向上渐隐；纯图片卡片保留约 22% 的薄玻璃。纯文字卡片继续使用中性底色。
- 扩散颜色来自当前封面可见区域的下缘，左右分别取色，只在图片下缘形成柔和阴影，不给整张卡片加持续变化的光晕。
- 每张封面在每种展示比例下最多进行一次 **24 × 8 像素**的本地采样；复用已加载图片，不上传像素，不另取图片，不绑定滚动或逐帧动画。跨越手机断点导致裁切比例改变时取另一份颜色，两种结果复用；普通尺寸变化和反复滚动不会重复取色。
- 取色失败、画布不可用、跨域限制或透明图片无有效颜色时，立即保留中性材质，文字与图片入口继续可用。图片加载失败时隐藏玻璃与扩散，显示现有失败提示。
- 减少透明度和高对比模式移除模糊与扩散，文字切换为清晰实色。没有 JavaScript 时保留默认裁切、底部材质与真实详情链接，不依赖增强代码才能阅读。

## 详情与原图

列表是预览，详情用于看完整画面：桌面左侧图集、手机横向图集均使用 `contain`，不继承列表裁切。比例不同产生的剩余空间使用站点中性底色，不拉伸或复制图片填充。

图片预览继续展示完整原图，保留前后切换、关闭、键盘和原生图片链接；分享 URL 指向公开动态，不能改变图片的访问权限。

## 发布图片建议

按内容选择图片，不要求全部做成竖图：人物、海报适合 3:4 或 4:5；风景、桌面截图适合 3:2 或 16:9；近方形图会统一为 1:1。主体尽量放在中央，底部避免放重要文字、人脸或必须完整展示的细节。超长截图从顶部预览，超宽全景与细节较多的图片可在详情查看完整内容。

目前没有自动识别人脸、主体追踪或作者自定义焦点。后续如增加焦点坐标，应同时用于裁切、取色和创作预览，而不是分别计算。
