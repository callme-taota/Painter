# V23：沉浸游戏墙与公开歌单唱片墙

本轮扩展已有首页：游戏墙通过原生滚动进入和退出遮罩，每款游戏用实际 Steam 大图、官方字标或真实标题及已知游玩时长展示；首页最多五款，更多进入完整的 `/games`。相邻的唱片墙承接游戏退出，专辑封面紧贴铺满。后台保留 V22 的三个任务页签和中性控件，不改变现有视觉世界或共享 token。

**当前状态：V23已发布到正式局域网入口，schema19。候选验收、独立视觉评审、正式迁移、正常owner接口配置激活及104项只读LAN冒烟全部完成。视觉裁决限定为已检查的截图和行为证据；[完整证据汇总](../tests/artifacts/v23/summary.json)保留实际数据与验收边界。**

## 游戏墙与完整游戏库

在 owner 的 `/studio/home` →「页面内容」开启游戏墙。首页数量为0时隐藏；其它正数最多展示前五项。存储和管理控件仍允许0–24，兼容已有8、24等设置，不因本轮升级重写旧值。条目顺序仍由已保存的 `(position,id)` 决定。

「查看更多」固定进入站内 `/games`，后台只编辑链接文字，留空使用「查看更多游戏」；地址明确只读，避免保存无效配置。完整游戏库不受首页五项上限或首页数量0影响，按可见条目分页；关闭游戏墙开关时公开游戏库也关闭。

`/games` 的「展示顺序 / 游玩时长 / 名称」使用普通链接，对应 `sort=position|playtime|title`。默认按展示顺序；时长降序、未知置后，各排序使用 ID 稳定分界。游标绑定排序和每页数量，切换条件须从第一页重新读取，不能沿用另一排序的游标。API 每页最多50项；界面计数来自实际可见条目，不虚构完整游戏时长或收藏统计。排序、翻页及商店链接无需 JavaScript。

### 素材与真实时长

Steam 读取公开信息和同步时，优先使用提供方返回的精确 hero / logo 素材路径，包括带版本或资源哈希的官方地址。旧条目可使用官方旧版素材回退；字标缺失或加载失败时显示保存的真实游戏名，不用虚构 logo。后台「沉浸展示素材与游玩时长」可填写官方 Hero / Logo 地址；留空表示自动素材。私有 DTO 返回原始存储值，公开 DTO 才计算回退，避免一次普通编辑把自动素材固化为人工覆盖。

累计时长以 `playtime_minutes` 保存，属于 Steam 提供方的只读统计，后台不能手工提交。`null` 表示未知，明确的新同步结果0表示实际0；公开显示分别为「时长未知」和0小时。旧解码器曾把缺失时长写成“0 分钟”，无法区分未知与真0，因此迁移保守保留为 `null`，等待一次新同步确认。只有可验证的旧正整数分钟、且未人工改写的同步记录才回填；不从近似小时或自定义副标题猜测。

人工标题、链接、图片、排序、隐藏状态和自选封面继续受到 `local_override` 保护；提供方只读时长仍可由新同步更新。删除同步游戏不等于永久屏蔽，下次同步可能再次出现，持续不公开应设为隐藏。既有 Steam 凭据配置、六小时可选同步和失败保留上次快照规则不变。

## 原生滚动、遮罩与静态阅读

增强首页以 `clip-path` 矩形窗口完成进入遮罩、最多五个全屏游戏场景和退出遮罩。真实大图与身份文字有不同层次的位移；滚动位置驱动当前场景，当前场景保持可访问，其它增强层不进入交互。游戏导航可用键盘，焦点导航会把相应场景带入视野。

游戏与音乐在配置顺序中相邻时，音乐的全屏封面墙粘附在退出窗口下方，随遮罩合拢自然接续，不加空白中场。两者不相邻时分别作为可读区块展示，尊重站长排序。专辑墙零间隙排列，底部克制呈现配置标题、实际歌单来源和官方 Apple Music 入口。

不拦截滚轮，不引入 WebGL、模型、自动播放或空闲 RAF 循环。已有首页「启用滚动视差」关闭、系统减少动态效果或无 JavaScript 时，最多五款游戏按正常文档流展开，专辑原生链接可直接打开；不会依赖遮罩才能读到内容。原有介绍纸页、文章展架、暖色背景设置仍各守原有范围。文章正文、照片墙、动态图片与站长资料不属于本轮改写范围。

## 公开 Apple Music 歌单导入

在「展示墙」选择「Apple Music 唱片」，展开链接导入，可粘贴专辑或公开歌单。单专辑仍保留 iTunes Lookup 路径；公开歌单使用匿名可读的已验证页面数据，不读取私人播放历史或私人歌单，不使用 MusicKit、开发者 token 或会员授权。

本轮实际检查的是用户给出的[逃塔喜欢的音乐](https://music.apple.com/us/playlist/%E9%80%83%E5%A1%94%E5%96%9C%E6%AC%A2%E7%9A%84%E9%9F%B3%E4%B9%90/pl.u-KVXBkAWuZqb1BXV)。2026-11-03 的同一 ID 中国区公开页面返回 **300首曲目、291张去重专辑**，并含后续分页标记，所以明确标记 `partial=true`。这不是完整歌单导出，也不是291首曲目。美国区原地址的同 ID 中国区回退经过来源、canonical 与页面身份校验，不把普通地区首页当作歌单。

流程分两步：

1. **读取歌单预览**：不创建展示墙条目；分别显示本次曲目数、去重专辑数、当前预览数。最多展示前24张专辑封面，24不代表本次只会保存24张，也不代表完整歌单。部分读取状态和来源链接始终可见。
2. **明确确认保存**：保存该份已核对快照中的去重专辑，不再请求 Apple。新歌单条目设为 `visible=true`，追加到已有顺序后；确认文案说明，音乐墙已开启且显示数量大于0时可立即公开展示。此语义不同于单条编辑器的新建条目，后者仍默认隐藏。

预览有效期30分钟；成功的公开页面元数据缓存24小时，缓存命中不延长原到期时间。「重新读取最新预览」可绕过缓存；过期须重新读取并确认。导入使用歌单来源的独立 CAS 版本，而不是首页配置版本。失败保留旧预览、输入、上次成功来源和已保存条目；未保存的条目或首页设置会阻止确认导入。网络结果未确认时保留原幂等键、版本和 `preview_id`，重试同一批次，避免重复创建。

重导按专辑 ID 去重：已有同 ID 手动条目不覆盖、不另建；已有歌单条目的人工修改、隐藏、自选图片、说明及排序保留，不删除本次快照之外的旧条目。当前版本没有音乐自动同步任务。读取更多完整歌单页不在本次实现内。

封面使用页面实际返回的 Apple artwork 模板及其最大尺寸，不把 `artworkUrl100` 字符串直接改成大尺寸。本轮首张专辑来源实测解码为 **632×632 JPEG**；其余素材受各自返回模板限制，不承诺所有旧小图已自动高清化。单专辑增强失败仍保留原 iTunes 返回封面，站长也可继续上传自己的高清封面。

公开页面的序列化格式不是稳定的官方数据接口，可能随 Apple 页面或地区目录变化。结构或身份不符合预期时读取失败并保留本地快照，不能承诺这一公开页面格式永久可用。研究、真实样本与请求边界见[音乐导入记录](../tests/artifacts/v23/music-import-review.md)。

### 正式迁移与主动配置分别核对

正式入口为 `http://192.168.2.209:18080`。发布前备份目录为 `/tmp/painter-next-before-v23-final-20261103`；已核对数据库归档列表、媒体归档、旧运行文件、私有环境文件及受限文件权限。正式晋升在停服边界比较54张旧表，已有字段的计数和哈希保持一致；`schema_migrations`只比较原1–17行，新增18 / 19另核对固定校验值。112条旧游戏中70条可确认正分钟完成回填，42条保持未知，无错误回填或意外Hero / Logo。媒体8个文件及环境文件保持一致，来源预览为空、来源状态为默认行。
