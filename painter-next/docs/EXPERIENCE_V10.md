# V10：编辑页比例与布局

本轮调整文章编辑页的视觉层级、空间比例和响应式布局。原来的标题、属性、模式与格式工具横向铺满，正文却在另一层窄容器内居中，文字起点不一致；顶部还有多条独立横带。现在形成一个连续写作区域，文章属性作为支持信息。

| 场景 | 布局 |
| --- | --- |
| ≥1360px 文档模式 | 居中最大1280px工作区；左侧标题、格式工具与正文为连续写作页，右侧280px文章信息栏，间距28px |
| 窄于1360px | 单列，文章信息在标题后默认折叠；展开仍是原生details，保留键盘操作 |
| Markdown源码 | 整个工作区用于编辑/预览/分屏；属性回到折叠行，不挤占两侧正文 |
| ≤600px | 缩小页面及正文内边距，命令栏换行；主要命令维持44×44px目标 |

标题与文档正文共享最大850px文本容器和相同左右内边距；实际测试四种宽度的文本起点差为0px。顶部任务标题、保存状态、返回/保存/检查点/撤回/发布合为一层命令栏，使用实色背景与底部细线，滚动后保持可达。模式切换、格式工具属于写作面，不再各自成为独立卡片。

文章摘要、可搜索标签、三种时间开关和封面选项均保留，宽屏默认展开，栏内独立滚动；折叠或调整布局不会保存或修改文章。封面下拉仍使用项目自定义控件，预览使用现有真实接口。所有属性只渲染一份；没有复制DOM、隐藏副本或引入新编辑器。

## 保存和内容合同

本轮只在MarkdownEditor增加属性展开状态的屏幕/模式适配，重排模板并增加专属editor-layout.css；DocumentEditor为段落选择器增加实际包装元素，使布局类和可访问名称正确配合。保存、离线恢复、CAS、图片、Markdown保留、不可变修订、发布和撤回协议不变。

错误、上传、本地恢复、尚未同步新稿及冲突比较仍在正常页面流中明确展示；修订与公开文章入口保留。未发布修改不会因调整布局出现在公开文章中。没有新迁移、运行服务或依赖，schema保持12。

## 验证

- 173项只读布局与交互断言，涵盖1920/1440/900/390宽、标题/正文起点、属性响应式、源码三视图、键盘与44px目标；内容/元数据/版本指纹保持不变。
- 复用原21项真实文档集成断言，覆盖Markdown原样、自动/手动保存、图片、检查点、发布、修订恢复和撤回。
- 两批同路径24张浅深截图；首批发现组件scoped样式覆盖命令尺寸，修正选择器和最小宽度后第二批为最终证据。没有增加自发精修轮次。
- 原恢复脚本仍使用历史原生select，V10另存适配副本，只更换为实际combobox交互/值读取，保留原离线、慢响应、丢响应与恢复断言。

实际通过项、独立审阅、恢复结果与正式局域网切换记录见[验收](VALIDATION.md)和[汇总](../tests/artifacts/v10/summary.json)。当前版本仅布局优化，不代表前一轮评估的后台通用表单、部署持久化或账号生命周期缺口已处理。
